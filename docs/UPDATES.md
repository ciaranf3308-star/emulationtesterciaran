# Crystal Frontend — Signed Auto-Updater (V8.3.1)

This document describes the official Tauri v2 signed updater for Crystal installed on ROG Ally (Windows).

> **Philosophy:** Updates come ONLY from signed GitHub Release artifacts. We never execute arbitrary JS from `main`, never `git pull` inside the installed app, never touch EmuDeck / ES-DE / ROMs / BIOS / saves / gamelists / scraped media. Only Crystal binaries/assets are replaced.

---

## 1. Architecture

- **Rust plugin:** `tauri-plugin-updater` added to `tauri::Builder::default().plugin(tauri_plugin_updater::Builder::new().build())` in `src-tauri/src/main.rs`.
- **Public key:** Embedded in `src-tauri/tauri.conf.json` → `plugins.updater.pubkey` (base64 ed25519 32-byte). Safe to commit.
- **Private key:** NEVER committed. Lives only in:
  - Secure local `~/.tauri/crystal.key` (for `tauri signer generate`)
  - GitHub Actions secret `TAURI_SIGNING_PRIVATE_KEY`
  - Password secret `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` (if used)

- **Endpoint:** `https://github.com/ciaranf3308-star/emulationtesterciaran/releases/latest/download/latest.json`

  This file is generated by the release workflow. For each platform (Windows x64) it contains:

  ```json
  {
    "version": "v4.3.1",
    "notes": "Crystal v4.3.1 changelog",
    "pub_date": "2026-08-10T00:00:00Z",
    "platforms": {
      "windows-x86_64": {
        "signature": "dW50cnVzdGVkIGNvbW1lbnQ6 ... minisign sig from .sig file",
        "url": "https://github.com/ciaranf3308-star/emulationtesterciaran/releases/download/v4.3.1/Crystal-Frontend_4.3.1_x64_en-US.msi.zip"
      }
    }
  }
  ```

- **Frontend service:** `src/updater/crystalUpdater.ts` wrapper around `@tauri-apps/plugin-updater`:
  - `checkForUpdate()` → non-throwing, returns `null` if offline/no update
  - `downloadAndInstallWithProgress(cb, rawUpdate)` → elegant progress (chunkLength/contentLength), delegates to official plugin which validates signature before install
  - `installAndRestart()` → explicit user confirmation required before restart
  - Logs to Crystal-local logs `%LOCALAPPDATA%\CrystalFrontend\logs\crystal-frontend.log` via `safety::log_event`

- **UI:**
  - **Startup check** (App.tsx): fire-and-forget after 1.8 s, never blocks first paint. If `null` → silent noop. If available → bottom-right restrained glass card `Crystal vX.X.X available` `[UPDATE]` `[LATER]` – intact Golden Screens, no full-screen block.
  - **Download progress:** thin line bar inside card, `12% … 100%`.
  - **Confirm dialog:** `Install Crystal vX.X.X now? App will restart.` `[INSTALL NOW]` `[CANCEL]` – explicit confirmation required.
  - **Failure recovery:** catch, toast `Update failed – kept current version`, current install remains usable, never auto-damages.
  - **Manual:** Settings → `CHECK FOR UPDATES` button with states Idle/Checking/Available/Up-to-date/Error, progress line, version/commit/stack diagnostics, endpoint display.

## 2. V8.1 Safety Preserved

- `src-tauri/src/safety.rs` untouched – write guard ensures `crystal_writable_root()` is only descendant writable area.
- `is_safe_write_path` rejects empty, `/`, `\`, drive root `C:`, `traversal`, `junction/symlink escape`, `EmuDeck`, `ROM/media`, `arbitrary external` → fail closed.
- Updater **never** writes to ROMs, BIOS, gamelists, scraped media, EmuDeck, ES-DE themes, user saves. Tauri updater replaces binaries in `Program Files/CrystalFrontend` only (MSI/NSIS install dir) – not user data dirs.
- `CRYSTAL_SAFE_MODE=1` handling still works: frontend reads `get_safe_mode`, blocks launcher UI, backend `launch_game` aborts even if frontend bypassed.
- Capabilities trimmed to `updater:default`, `allow-check`, `allow-download-and-install`, `allow-download`, `allow-install` in addition to existing 23 perms (now 28 total). No `fs:allow-write` expansion, no arbitrary `shell:allow-execute`. Auth audit docs preserved.

## 3. Key Management

### Generating a new keypair (dev machine, offline)

```bash
# install tauri-cli if missing (requires cargo)
cargo install tauri-cli --locked

mkdir -p ~/.tauri
tauri signer generate -w ~/.tauri/crystal.key
# Outputs:
# ~/.tauri/crystal.key      -> private key (NEVER COMMIT)
# ~/.tauri/crystal.key.pub  -> public key (base64, commit this to tauri.conf.json)

# View public key
cat ~/.tauri/crystal.key.pub
# Example: gMqZ8bVKU26sQqirx7TX7H+j67/TgPj3Kh747WWVfOU=
```

For this repo, a random ed25519 pair was generated via Python `cryptography` in `/tmp` for V8.3.1 initial public key. Private seed `h73VhySSVpt8dxRybUmwcuinkwhqpCtHLMOXfskZUow=` was **NOT** committed; public `gMqZ8bVKU26sQqirx7TX7H+j67/TgPj3Kh747WWVfOU=` is in `tauri.conf.json`.

> Real production deployments should regenerate a fresh pair on an air-gapped machine and replace the public key – previous published releases will then require manual reinstall (one-time) because old pubkey won't validate new signatures. Plan this before first public Windows installer distribution.

### Required GitHub Secrets

In Repo > Settings > Secrets and variables > Actions > New repository secret:

| Secret | Value | Notes |
|--------|-------|-------|
| `TAURI_SIGNING_PRIVATE_KEY` | Contents of `~/.tauri/crystal.key` (full base64 64-byte private) | `cat ~/.tauri/crystal.key` paste entire line, no newline trimming. Used by tauri-action signer. |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | Password if you set one during `tauri signer generate` | If empty password, omit secret or set empty string – action tolerates empty. |

Optional local env for manual build:

```bash
export TAURI_SIGNING_PRIVATE_KEY=$(cat ~/.tauri/crystal.key)
export TAURI_SIGNING_PRIVATE_KEY_PASSWORD="your-pw"
npm run tauri build
```

`.gitignore` already ignores `*.key` (line 46) – double-checked.

## 4. Release Infrastructure

### Workflow: `.github/workflows/release.yml` (new in V8.3.1)

Triggers:
- On tag push `v*.*.*` (e.g. `v4.3.1`) – recommended for production
- Manual dispatch (`workflow_dispatch`) with input `tag` for pre-release dry-run

Jobs:
- `build-windows`: `windows-latest`, steps:
  - checkout, setup-node 20, setup-rust stable, setup bun, cargo tauri-cli install
  - `bun install --frozen-lockfile`
  - Build: `TAURI_SIGNING_PRIVATE_KEY=${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}` `TAURI_SIGNING_PRIVATE_KEY_PASSWORD=${{ secrets.TAURI_SIGNING_PRIVATE_KEY_PASSWORD }}` `npm run tauri build` (generates `src-tauri/target/release/bundle/msi/*.msi`, `nsis/*.exe`, plus `*.msi.zip` + `*.msi.zip.sig`, `*.nsis.zip.sig` for updater)
  - Generate `latest.json` manifest:
    - Parses version from `Cargo.toml` / `package.json`
    - Builds platforms map from artifacts (windows-x86_64 url + signature)
    - Writes `dist/latest.json` (copy to `latest.json`)
  - Upload to GitHub Release via `softprops/action-gh-release` – attaches msi/nsis + zip + sig + latest.json

Example manifest snippet stored in release assets:

```json
{
  "version": "v4.3.1",
  "notes": "See GitHub release notes",
  "pub_date": "2026-08-10T00:40:00Z",
  "platforms": {
    "windows-x86_64": {
      "signature": "CONTENT OF .msi.zip.sig",
      "url": "https://github.com/.../releases/download/v4.3.1/Crystal-Frontend_4.3.1_x64_en-US.msi.zip"
    }
  }
}
```

`latest.json` is also served via `releases/latest/download/latest.json` endpoint (GitHub redirect). Tauri updater follows redirect, validates `pubkey` against signature before installing.

## 7. Failure Recovery

All paths catch errors:

- Network down at startup → `checkForUpdate` returns `null`, no banner, log at debug level `Crystal-local logs` line `[info] crystal-frontend startup safe_mode=…`
- No GitHub release → 404 on latest.json → check returns `null` → startup continues
- Download interrupted → chunkLength stream aborts, catch clears `downloading` flag, shows `Update failed – kept current version`, current MSI remains untouched (Tauri writes to temp then validates sig before overwriting)
- Signature mismatch → plugin rejects install, returns error, frontend shows `signature invalid – kept current`, logs warning `log_event("warn", ...)`
- User presses LATER / CANCEL → banner dismissed, no auto-retry until next app start or manual check
- Current app remains usable if check fails – no forced exit, no blocking overlay

## 8. Do NOT Do

- Do NOT publish a fake production release merely to satisfy testing. The workflow creates releases only when you push a tag `v*.*.*` or manually trigger. No v* tags have been pushed yet for this test pass – manifest example lives in docs only.
- Do NOT commit private keys.
- Do NOT replace `main` with updater artifacts.
- Do NOT add `git pull` logic inside Tauri runtime – that would violate EmuDeck/ES-DE read-only policy.
- Do NOT touch `Crystale` selective filesystem guard.
